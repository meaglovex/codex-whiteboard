# 0.1.2 对话驱动白板验收

日期：2026-09-30。本次修正针对“用户不手动编辑产品，Codex 识别新产品意图后自动建板，并随当前聊天更新”。

## 实现与本机安装

- 默认交互改为展示：移除新建、编辑、图片上传、连线、采纳、钉住、重复聊天框和工具栏；保留展开依据、查看全部及收起的历史/导出选项。
- 使用官方 shadcn/ui Base Nova 组件与 neutral tokens。多媒体、流程和可试用交互原型仍可由 Codex 写入；下层用递归 Accordion 展开。
- `whiteboard_begin` 将产品标识与聊天范围绑定，重试复用同一白板。`whiteboard_sync` 按稳定 ID 增量更新卡片、讨论和关系，递归保留未修改依据。
- Skill 声明新产品的隐式触发，`agents/openai.yaml` 允许隐式调用；当前聊天负责讨论、反驳、例子、偏好与写回。桌面提供打开能力时必须自动打开并检查回执；CLI 只能返回链接时如实说明。
- 本机已安装并启用 `product-whiteboard@product-whiteboard-local` 0.1.2。安装器核对前端、MCP、清单、Skill、隐式调用策略、文档与 notices 的 SHA-256 一致性；5210 运行的是安装缓存中的服务。
- 用户试用页实际从旧编辑界面刷新为对话驱动界面，展示本次产品讨论的三张核心卡片。旧日记示例 revision 4 保留。

## 验证结果

`npm test`：15/15 通过。覆盖 MCP/面板资源、受限桥接、图片读回、来源与认证限制、落盘、并发冲突、完整导出，以及新的幂等建板、同卡更新、讨论重试去重、多层内容保留、活动页刷新和失败不写盘。

`npm run verify:host`：真实 Codex app-server 加载新建与同步工具；读取 `ui://product-whiteboard/board-v0.1.2.html` 及 thread 入口声明；安装的 Skill enabled，加载错误为空。

第一次真实模型验收：`.test-data/implicit-9Y6Zy2/acceptance.json`（私有、Git 忽略）。自然语言提示没有提到白板、插件或 Skill。第一轮主动调用 preferences → begin → sync → read，创建一页、写入五张核心卡片；第二轮用户反驳即时分类，自动更新同页并记录“先收下再整理”共识，revision 3 → 4。另一临时聊天提出已有保存按钮失效，没有触发新建。此轮使用已安装 Skill 与同版本打包 MCP，测试服务隔离在 5334。

最终安装包真实模型复验：`.test-data/implicit-UqygDu/acceptance.json`。使用已安装缓存中的 MCP 和 Skill，通过显式测试环境覆盖隔离数据；同样通过自然意图、反驳写回、普通修复不建页三个回合，revision 3 → 4，五张核心卡片。曾遇到模型采用下划线卡片 ID 被拒绝；后续将纯内容引用 ID 与文件路径白板 ID 分开校验，支持下划线，单元场景已覆盖。文件路径白板 ID 与认证边界不变。模型额度检查单独运行，不纳入默认单元测试。

真实 MCP Apps 验收宿主：保持页面不刷新，调用 begin 后自动切到空白新页；调用 sync 后卡片出现；三层依据展开后再次同步，标题、反驳文字实时改变，展开状态及原有更深内容保留。原型输入→提交→完成反馈、历史白板→恢复跟随均通过，检查的控制台错误/警告为空。测试数据与用户资料隔离，验收宿主和测试页已关闭。

本机安装界面：正常宽度可显示三张核心卡片；520 px 窄侧栏采用可读的单列卡片与滚动画布，流程纵向展开，产品标题与画布分开，不混入卡片内容。验收后恢复正常宽度。

## 验证边界

隐式识别由 Codex 的 Skill 选择与模型遵循规则实现，不能保证每次语句都硬触发。没有新增全局 Hook 或额外信任要求。

临时 CLI 验收环境没有可用的内置浏览器，模型尝试打开后回到链接交付；这不能证明桌面能自动弹出新页。当前聊天的 `open_in_codex` 返回 queued，仅说明排队；已经实际查看的是用户打开的本机页面。桌面新聊天中的自动开页、原生“更多工具”菜单实显仍需用户试用确认，未写成已验收。

未配置 Git 远程、未公开发布市场；本次交付范围是本机 0.1 试用。
