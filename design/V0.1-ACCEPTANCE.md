# 产品白板 0.1 本机验收

日期：2026-09-30。结论：0.1.0 已完成本机安装并启用，宿主可调用工具，网页在已安装缓存目录中运行。公开市场发布尚未进行。

## 安装与宿主

- 插件 ID：`product-whiteboard@product-whiteboard-local`。CLI 返回 `installed=true`、`enabled=true`、版本 `0.1.0`。
- 安装目录：`~/.codex/plugins/cache/product-whiteboard-local/product-whiteboard/0.1.0/`。
- `npm run install:local` 实际运行通过，前端、MCP、服务端与 Skill 的源包/安装文件哈希相同。服务进程确实从安装目录启动，不是 Vite 视觉预览。
- Codex CLI 0.159.0 的实际 app-server 临时会话加载七个工具，并成功调用 `whiteboard_open`；Skill `product-whiteboard:product-whiteboard` 启用，加载错误为空。没有启动模型回合来模拟宿主加载。
- 七个工具：open、list、read、apply、preferences、export、image，均带 `whiteboard_` 前缀。

## 真实行为

1. 在已安装网页中新建“验收 · 分层讨论”，填写产品目标及三个融合参考，得到独立空白产品。
2. 向真实 Codex 提出“第一屏展示所有细节”。它主动反对，说明可读性与遗漏的关系，并举退款流程、白板和原型的具体例子。
3. 点击“反驳这点”，提出关键异常不应隐藏。模型承认第一轮方案不足，修正为“核心精简，关键风险直接可见”，使用同一个退款场景回应。两轮均产生真实候选；没有固定答复或测试模型替身。
4. 采纳候选后仍未钉住；再由界面明确钉住。编辑第二层重要异常，补充第三层幂等提交；刷新与服务更新后原文及钉住状态保留。
5. 新建流程图，将三步改成“申请→审核→到账”；新建原型，修改标题、动作、输入提示与完成反馈，实际输入并提交，看到自定义反馈。原型的演示输入是临时界面状态。
6. 经文件选择器导入真实 JPG，显示实际风景图片；移出后撤销，节点恢复。
7. 点击保存文件，JSON 与 Markdown 实际落盘；回读确认四个节点、真实内嵌图片、第三层依据、原型配置及尚未采纳的候选。随后将 JSON 从文件选择器导入，创建独立新 ID，完整内容保留。
8. 产品切换后地址和标题跟随当前产品；重新打开恢复正确产品。偏好界面显示有来源的中文沟通习惯，未知技术栈为空；MCP 写入和文件读取一致。
9. 同字段冲突保护、独立并发合并、跨站拒绝、未授权写入拒绝、非法图像与连接校验由自动测试覆盖。

两份人工验收白板及其保存历史已移动到本机数据目录 `acceptance/2026-09-30/`，未删除。正式列表保留干净的“慢一点”示例。示例的三条预置讨论不计入真实模型验收。

## 检查结果及边界

- TypeScript 与 Vite 生产构建通过，插件打包通过。
- `npm test`：11/11 通过，包含真实 MCP 握手、实际图像、权限、文件落盘、并发冲突与开发导出。测试使用独立临时目录，不改用户白板。
- 已安装网页的 console error/warn 为空；正常窗口与窄屏实际显示通过，临时视口覆盖已恢复。
- Vite 开发代理实际加载白板与保存状态通过。开发环境出现 React Flow 的署名支持提醒，生产环境没有此提醒；未隐藏或篡改日志。安装包保留运行时依赖的版权与许可证全文。当前 React Flow 包为 MIT，维护者对界面署名的说明见 [官方讨论](https://github.com/xyflow/xyflow/discussions/4812)。
- 安装只注册本插件的本机市场，不创建远程仓库、外网部署或开机启动。
- 0.1 用 stdio MCP 本机试用。没有公开市场审核、任意原型页面编辑、多人同步、云账户；宿主完整记忆不会自动被扫描，可靠可见偏好由 Skill 写回。
- 模型联网讨论使用 Codex 登录与额度；讨论中出现的“原型联动”等方案是待讨论的产品想法，不代表本白板已自动实现相应业务。
